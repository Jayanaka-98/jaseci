- **Audio inputs and return-type-driven media outputs in byLLM**: a new `Audio` type carries clips into any `by llm()` call on an audio-capable model, serializing to an `input_audio` block that reaches OpenAI verbatim and Gemini as `inline_data`. Declaring `Image` or `Audio` as the *return* type now asks the model to produce that medium, with the transport resolved from the model's capabilities; `save(path)` writes either to disk, and `Audio` returns carry their `transcript`. The dedicated `image_generation`/`speech`/`video_generation` endpoints are not routed yet, and a return type needing one raises `ConfigurationError` naming a model that works. (#8809)
